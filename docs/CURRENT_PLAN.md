# 현재 작업 계획 — 2026-10-25

다른 채팅·에이전트는 이 파일과 [최신 MVP](MVP.md)를 먼저 읽는다. 사용자 최신 직접 지시가 문서보다 우선한다.

## 사용자가 확정한 결정

- **1A:** 법규·판례는 사고 도표번호 `chart_no`로 JSON을 정확조회한다. PDF 청킹·임베딩·Chroma·검색형 RAG는 이번 제출 필수 범위에서 제외한다.
- **2A:** 현재 YOLO 첫 차량 검출 프레임 저장 기능을 유지한다. 화면·문서에는 ‘차량 감지 장면’으로 표시하고 사고·충돌 탐지라고 설명하지 않는다.
- **3A:** 기존 서버·화면에 연결하는 최소 코드 수정을 허용한다. 기존 문답·답변 저장·수정·질문 JSON과 DB 구조는 유지한다.
- 기능 범위·도구·설치 등 새로운 결정은 사용자를 대신해 채우지 말고 질문한다. 새 패키지·모델·플러그인의 다운로드·설치는 항목·출처·위치·변경을 제시한 별도 승인이 필요하다.

## 현재 확인한 기반

- 실제 앱은 이 문서의 상위 저장소 루트에 있다.
- 이 파일은 사용자 문서 작업공간의 현재 작업 계획을 저장소에 동기화한 문서다.
- main은 `1740f90`까지 pull 완료. 기존 문답·답변 수정·영상 업로드·차량 감지·사진 비교/확대가 있다.
- `origin/feature/langchain-rag`에는 JSON 자료와 독립 검색 스크립트가 있다. 브랜치 전체를 합치는 대신 필요한 데이터와 작은 연결 코드만 반영한다.
- 현재 앱은 HTML/CSS/JavaScript + Python WSGI + SQLite다. Next.js/FastAPI로 다시 만들지 않는다.
- 법규·판례 데이터는 `data/legal_references_by_chart.json`: 108개 도표 법규, 77개 도표 판례·조정사례. 제공 PDF에 판례가 없는 31개 도표는 빈 결과로 안내한다.
- 완료 세션의 서버 내부 `sessions.get_context(session_id)['chart_no']`를 사용한다. 내부 context 전체를 공개하지 않는다.

## 추가 확정 사항

사용자가 후속 선택 질문에 답했다.

1. **저장된 협회 비율·해설 사용.** 실시간 검색과 AI 생성은 이번 제출에서 제외한다. Tavily API 키·Ollama·LLM/임베딩 모델·RAG용 추가 패키지를 준비하지 않는다. 기존 YOLO 실행 환경 준비는 아래 별도 승인 기록을 따른다.
2. **자료의 차량 A/B로 표시.** 내 차·상대 차로 추정하지 않고 별도 차량 지정 질문도 추가하지 않는다.

비율·기본 해설은 `origin/feature/langchain-rag`의 `data/accident_cases.json` 108개 자료를 사용한다. 저장 자료임을 표시하고 원문 출처를 유지한다. 현재 남은 기능 범위 결정은 없다. 새 범위가 생기면 다시 질문한다.

## 작업 순서와 담당 파일

| 순서 | 작업 | 파일·책임 | 상태 |
|---|---|---|---|
| 1 | 확정 범위와 불필요한 기존 요구 정리 | 메인: 이 문서, MVP·기술구현 정의서 | 완료 |
| 2 | 완료 문답의 도표번호로 법규·판례 조회 | 메인: result_service.py, app_server.py, data/legal_references_by_chart.json | 완료 |
| 3 | 결과 화면·자료 없음·출처·페이지 표시 | 화면 담당: web/app.js, web/style.css | 완료 |
| 4 | 저장된 협회 A/B 비율·기본 해설 연결 | 메인: 결과 서비스, data/accident_cases.json, 화면 | 완료 |
| 5 | 변경 부분만 검수·공유 문서 갱신 | 메인: 결과 연결 검사, docs/CURRENT_PLAN.md, HANDOFF.md | 완료 |

연결 코드를 기존 앱에 반영했다. 여러 에이전트가 같은 파일을 동시에 편집하지 않는다.

## 최소 완료 조건

- 문답 완료 및 영상 업로드 확인 후 결과를 제공한다. 영상 미검출·처리 실패 안내와 법규·판례 결과는 분리한다.
- 법규·판례에 원문·출처 URL·PDF 이름·1부터 시작하는 페이지를 표시한다. 없는 판례를 생성하거나 유사 판례를 임의로 대신 붙이지 않는다.
- 답변 수정으로 revision이 바뀌면 기존 영상·결과를 폐기한다. 늦은 응답이 새 결과를 덮지 않게 한다.
- 과실비율·해설은 협회 JSON의 실제 값과 원문만 표시한다. 자료의 A/B 구분을 유지하고 저장 자료를 실시간 검색 또는 AI 생성 결과라고 표시하지 않는다.
- 광범위한 코드리뷰·모델 학습·성능 실험 대신 변경 경로에 한정해 가볍게 확인한다.

## 이전 문서 처리

기존 docs/TEAM_HANDOFF.md와 docs/evidence는 수집·문답 구현의 과거 기록이다. 완료된 수집·문답 작업을 처음부터 재실행하지 않는다. 현재 요구사항은 최신 MVP와 이 파일을 따른다.

## Windows 로컬 YOLO 실행 환경 준비 — 2026-10-25

- 사용자가 YOLO 실행 패키지·필수 하위 의존성·공식 모델 다운로드와 서버 재시작을 명시 승인했다.
- 앱 전용 .venv에 ultralytics 8.4.183, opencv-python 5.0.0.93, torch 2.14.1+cpu, torchvision 0.29.1+cpu와 필수 의존성을 설치했다. pip check 통과.
- 공식 Ultralytics assets v8.4.0의 yolo26n.pt를 models 폴더에 준비했다. CUDA 빌드가 아닌 CPU 전용이다.
- 실제 YOLO로 직접 생성한 1초 검은 영상을 처리해 no_detection을 확인했다. 이는 실제 차량 검출 성공률·주행 영상 속도 평가가 아니다.
- 기존 runtime/webapp 데이터를 유지해 .venv 서버를 재시작했고 http://127.0.0.1:8010/app-config의 model_ready=true를 확인했다.
- 브라우저를 새로고침한 뒤 짧은 주행 영상을 업로드하면 된다. 다시 실행할 때는 저장소 루트에서 .\.venv\Scripts\python.exe app_server.py를 사용한다.
- 이번 승인은 기존 YOLO 실행 환경에 한정된다. Tavily·Ollama·RAG·새 모델 학습을 다시 도입하는 승인이 아니다.
