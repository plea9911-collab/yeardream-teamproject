# 배포 코드·실측·보존 검증 (2026-10-23)

## 결론

현재 신규 배포 1순위는 AWS Lightsail Linux 2GB/60GB/public IPv4 월 $12 구성입니다. 백업·세금·도메인·전송량 초과는 별도입니다. 실제 Linux 메모리 부하는 아직 미검증이므로 최소 충분 사양을 보장하는 수치가 아니라 여유를 둔 첫 시도 사양입니다. 서버 운영과 HTTPS 설정은 추가로 필요합니다.

Railway는 편의성 측면에서 후보였지만, 2026-10-23 확인한 공식 상태 페이지에 보안 조사와 빌드 중단이 표시되어 현재 신규 배포 추천에서 제외합니다. 기존 가입만 했다는 이유로 사용자 자료가 노출됐다고 추정하지 않습니다. 이 프로젝트의 비밀정보/데이터는 Railway에 올리지 않았습니다.

## 측정 방식

`python tools/benchmark_deploy.py runtime/samples/classroom.mp4`

Python3.12.14/macOS26.6.2 ARM64, CPU 실행. 실제 운영용 Waitress 프로세스를 별도로 실행하고 HTTP로 문답 생성→영상 업로드→결과 조회합니다. 20ms 간격으로 서버 프로세스 RSS(물리 메모리에 올라와 있는 양)를 샘플링하고 CPU 시간을 기록합니다. 클라이언트·테스트 영상 생성 메모리는 제외합니다. 최초 실행은 프로세스 시작 후 최초 모델 로딩을 포함하지만 OS 파일 캐시까지 비우지는 않았습니다. 네트워크는 로컬이며 클라우드 전송·TLS 시간은 포함하지 않습니다.

실제 영상: 수업 YOLO/sample.mp4, 8,585,510바이트, 720×1280, 30fps, 790프레임(약26.33초). 첫 프레임에서 5대 감지되어 종료합니다. 영상 전체를 분석하는 데 걸린 시간으로 해석하면 안 됩니다.

| 사례 | 1차 시간 | 2차 시간 | 두 측정 중 최대 RSS |
|---|---:|---:|---:|
| 실제 영상 최초 요청 | 3.168초 | 1.886초 | 327.33MiB |
| 실제 영상 반복 1 | 0.248초 | 0.130초 | 326.61MiB |
| 실제 영상 반복 2 | 0.321초 | 0.247초 | 389.19MiB |
| 2분 720p 검은 영상 전체 검사 | 10.520초 | 4.880초 | 395.42MiB |
| 1초 4K 검은 영상 | 미측정 | 0.229초 | 330.89MiB |

검은 영상은 경로/자원 검사 목적의 합성 입력이며 인식 정확도 검증이나 최악 부하 보장은 아닙니다. 2분 4K 실제 영상, 최대200MB 동시 업로드와 장기간 반복 부하는 미검증입니다. Mac 메모리 압축/회수와 CPU 차이가 크므로 이 RSS를 Linux 청구 메모리로 간주하거나 512MB 요금제가 충분하다고 결론 내리지 않습니다. 2초 후 유휴 RSS도 12~15MiB로 줄어들어 요금 추정의 평균 메모리로 쓰지 않았습니다.

원시 결과: benchmarks/mac_run1.json, mac_run2.json. 초기 결과와 반복 결과를 모두 보존했습니다.

## DB·영상 보존 확인

기존 사용자 테스트 폴더를 덮어쓰지 않고 새 임시 runtime에서 수행했습니다.
- 실제 API로 문답 완료 및 실제 YOLO 작업 실행.
- 서버 프로세스 종료 후 같은 데이터 폴더로 재시작: 세션 응답 동일, 원본 JPEG 해시 동일.
- 입력 영상·사진·job.json 전체 SHA-256 해시 대조: 2차 실행의 16개 파일 동일.
- 서버가 멈춘 상태에서 전체 데이터 폴더 백업→별도의 빈 폴더로 복원→새 서버 프로세스 시작→같은 검증 통과.
- SQLite backup API 백업도 확인: 세션1개/답변5개. 전체 시험 데이터 약28.8MB.

이는 로컬 프로세스 재시작과 파일 백업 복원 검증입니다. 실제 클라우드 디스크의 재배포·장애·스냅샷 복원은 아직 수행하지 않았습니다. 배포 완료 판정 전 해당 검증을 추가해야 합니다. 자동 백업도 아직 활성화한 것이 아닙니다.

## 비용 비교: 측정값과 가정을 분리

Railway 요금식은 RAM $10/GB-month, CPU $20/vCPU-month, 볼륨 $0.15/GB-month, 송신 $0.05/GB. Hobby 최소 $5이며 포함 사용량을 중복 가산하지 않습니다.

예시 가정: 30일 상시 실행, 평균 RAM 0.5GB 또는 1GB, 하루20건, 건당 CPU30초(측정 최대19.208초보다 여유를 둔 가정), 저장5GB, 송신1GB. CPU 약$0.14 + 저장$0.75 + 송신$0.05:
- 평균0.5GB일 때 약 $5.94/월
- 평균1GB일 때 약 $10.94/월

이것은 실제 예상 청구 확정치가 아니라 민감도 계산입니다. 백업·세금 등 별도이며 Linux에서 평균 RAM과 CPU를 측정해야 합니다. 2GB를 평균으로 계속 쓰면 같은 가정에서 약$20.94가 됩니다.

Lightsail 2GB/60GB/public IPv4 서버 $12/월은 자원 사용량 변동에 덜 민감하지만 OS 보안 업데이트, HTTPS, 백업 운영이 필요합니다. Render 2GB 서버 $25+5GB디스크 $1.25=$26.25/월(추가 비용 제외)은 현재 비용 우선 요구에 비해 높습니다.

## 배포용 코드

- deploy_server.py: Waitress, 4개 HTTP 스레드, 분석1개/대기포함2개. 공개 사이트 사용자가 아닌 신뢰하는 팀원만을 위한 공용 계정 `team` + 24자 이상 비밀번호. 별도 사용자별 자료 격리는 없음.
- PUBLIC_ORIGIN: 실제 HTTPS 주소, DATA_DIR: 절대 영구 저장 경로, TEAM_PASSWORD: 서버 비밀 설정. 코드나 Git에 비밀번호를 넣지 않습니다.
- 호스트/다른 사이트 요청 거절, 미인증 화면/API/이미지 차단. /healthz는 비공개 데이터 없는 상태 응답.
- 로컬 app_server.py의 127.0.0.1 동작은 유지합니다.
- Dockerfile: Python3.12 + CPU 전용 torch/torchvision + 모델 빌드 시 준비. runtime/비밀정보/로컬 영상은 이미지에 복사하지 않습니다.
- deploy/compose.yaml + Caddyfile: Lightsail 등에서 HTTPS 앞단과 앱, 이름 있는 영구 볼륨을 구성합니다. 실제 도메인 DNS를 서버에 연결해야 합니다. 도메인이 없으면 확보/비용 확인이 선행됩니다.
- railway.toml은 대안 플랫폼용으로 보관합니다. Railway 환경에서는 DATA_DIR에 볼륨이 실제 연결됐는지 플랫폼 변수를 검사해 누락 시 시작을 거절합니다.

### Lightsail 준비 절차(아직 실행하지 않음)
1. Linux2GB/60GB/public IPv4 서버의 최종 요금 확인 후 생성. 고정 IP 연결, DNS 도메인 연결. SSH 접근 범위를 제한하고 웹용80/443을 엽니다.
2. 서버에 Docker/Compose 설치, 이 PR 브랜치 clone. 비밀 설정 파일은 Git 밖에서 관리하고 권한600 적용.
3. SITE_HOST=실제 도메인, TEAM_PASSWORD=무작위 긴 비밀번호를 Compose 환경에 전달합니다. `docker compose -f deploy/compose.yaml up -d --build` 실행. 환경 설정이 없으면 시작하지 않습니다.
4. app_data 볼륨에 SQLite와 videos가 생성되는지 확인. `docker compose down -v`는 자료를 삭제하므로 사용하지 않습니다.
5. HTTPS·팀 로그인·실영상·재시작 보존 확인. 앱을 정지한 상태에서 볼륨 전체 별도 백업, 별도 볼륨 복원 시험. 서버 자동 스냅샷과 별도 다운로드 백업을 설정합니다.
6. Linux에서 같은 벤치마크/사용 중 메모리를 확인한 뒤 링크 공유. 로컬 테스트 영상/DB를 서버로 자동 업로드하지 않습니다.

추가 자동 검사: 기존 문답26개, 연결·백업·배포인증11개 통과. 비밀번호/볼륨 누락 시 시작 거절도 검사했습니다.

### 검증 한계

Mac에 Docker 실행기가 없어 컨테이너 Linux 빌드는 아직 실행하지 못했습니다. Linux Python3.12용 지정 CPU wheel의 공식 배포 여부는 확인했습니다. Waitress 앱 자체는 실제 HTTP로 실행해 인증·영상·재시작·복원을 검증했습니다. 클라우드 자원 생성/결제/외부 업로드는 하지 않았습니다.
